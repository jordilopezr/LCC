# Signed Releases + SBOM in CI — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a tag-triggered GitHub Actions workflow that builds the four Linux artifacts in the existing podman containers and attaches keyless build-provenance, an SPDX SBOM (also keyless-attested), and SHA256 checksums, publishing a draft GitHub Release — closing threat-model T8.

**Architecture:** One workflow file (`.github/workflows/release.yml`) with two jobs — a build matrix (`ubuntu`, `almalinux`) that runs the existing packaging scripts inside the existing containers, and a release job that generates the SBOM from the source tree, computes checksums, creates provenance + SBOM attestations, and cuts a draft Release. The four packaging scripts get a one-line change so `VERSION` is overridable from CI while defaulting to `26H2` locally. A `docs/RELEASES.md` explains how to cut and verify a release.

**Tech Stack:** GitHub Actions, podman, existing bash packaging scripts, `anchore/sbom-action@v0` (syft), `actions/attest-build-provenance@v2`, `actions/attest-sbom@v2`, `gh` CLI.

## Global Constraints

- **No secrets.** Signing is keyless (Sigstore/OIDC) only. Never add a GPG or cosign private key, or any repository secret, to this workflow.
- **Action pins (verbatim):** `actions/checkout@v4`, `actions/upload-artifact@v4`, `actions/download-artifact@v4`, `anchore/sbom-action@v0`, `actions/attest-build-provenance@v2`, `actions/attest-sbom@v2`.
- **Permissions block (verbatim):** `contents: write`, `id-token: write`, `attestations: write`.
- **Version derivation:** tag `vX` → `VERSION=X` (strip a single leading `v`). Local builds with no `VERSION` env keep producing `26H2` artifacts unchanged.
- **Artifact names are load-bearing** — do not rename them. Ubuntu leg → `lightweight-cloud-connector_<V>_amd64.deb`, `lightweight-cloud-connector_<V>_x86_64.AppImage`, `lightweight-cloud-connector_<V>_amd64.tar.gz`. AlmaLinux leg → `lightweight-cloud-connector-<V>-1.x86_64.rpm`.
- **SBOM scope:** one `sbom.spdx.json` generated by scanning the **source tree** (Rust `native/Cargo.lock` + Dart `pubspec.lock`), attested to all four artifacts. Do not scan the packaged `.deb`/`.rpm` for the SBOM.
- **Release is a draft.** The final "create release" step must be a draft and must only run on a real tag push, never on `workflow_dispatch`.
- **Do NOT touch `docs/THREAT_MODEL.md`** — it does not exist on this branch (off `origin/main`); the T8 update happens at integration time.
- **No `Co-Authored-By` trailer on code commits.** It is permitted only on documentation commits (the spec/plan/`RELEASES.md` commits). `.github/workflows/release.yml` and the script edits are code — their commits carry no such trailer.

### Task 2: Release workflow `.github/workflows/release.yml`

**Files:**
- Create: `.github/workflows/release.yml`

**Interfaces:**
- Consumes: the `VERSION`-overridable packaging scripts from Task 1; the container images `packaging/podman/Containerfile.ubuntu` and `Containerfile.almalinux`.
- Produces: on a `v*` tag push, a draft GitHub Release with the four artifacts, `SHA256SUMS`, `sbom.spdx.json`, plus keyless provenance and SBOM attestations for each artifact.

- [ ] **Step 1: Create the workflow file**

Write `.github/workflows/release.yml` with exactly this content:

```yaml
name: Release

on:
  push:
    tags:
      - 'v*'
  workflow_dispatch:
    inputs:
      version:
        description: 'Version string for artifact names (e.g. 26H2). Dry run: builds + attests, no release.'
        required: false
        default: '26H2'

permissions:
  contents: write
  id-token: write
  attestations: write

jobs:
  build:
    name: Build (${{ matrix.image }})
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        include:
          - image: ubuntu
            scripts: 'package_deb.sh package_appimage.sh package_tarball.sh'
          - image: almalinux
            scripts: 'package_rpm.sh'
    steps:
      - uses: actions/checkout@v4

      - name: Derive version
        id: ver
        run: |
          if [ "${{ github.event_name }}" = "workflow_dispatch" ]; then
            V="${{ github.event.inputs.version }}"
          else
            V="${GITHUB_REF_NAME#v}"
          fi
          echo "version=$V" >> "$GITHUB_OUTPUT"
          echo "Building version: $V"

      - name: Build container image
        run: |
          podman build -t lcc-builder-${{ matrix.image }} \
            -f packaging/podman/Containerfile.${{ matrix.image }} \
            packaging/podman

      - name: Run packaging scripts
        run: |
          podman run --rm \
            -e VERSION="${{ steps.ver.outputs.version }}" \
            -v "$PWD:/workspace/src" \
            -w /workspace/src \
            lcc-builder-${{ matrix.image }} \
            bash -euo pipefail -c '
              for s in ${{ matrix.scripts }}; do
                echo "=== Running scripts/$s ==="
                ./scripts/$s
              done
            '

      - name: Collect artifacts
        run: |
          mkdir -p out
          shopt -s nullglob
          for f in *.deb *.rpm *.AppImage *.tar.gz; do
            cp "$f" out/
          done
          ls -lh out

      - uses: actions/upload-artifact@v4
        with:
          name: artifacts-${{ matrix.image }}
          path: out/*
          if-no-files-found: error
          retention-days: 7

  release:
    name: Attest & release
    needs: build
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Derive version
        id: ver
        run: |
          if [ "${{ github.event_name }}" = "workflow_dispatch" ]; then
            V="${{ github.event.inputs.version }}"
          else
            V="${GITHUB_REF_NAME#v}"
          fi
          echo "version=$V" >> "$GITHUB_OUTPUT"

      - name: Generate SPDX SBOM (source dependency graph)
        uses: anchore/sbom-action@v0
        with:
          path: .
          format: spdx-json
          output-file: sbom.spdx.json
          upload-artifact: false
          upload-release-assets: false

      - name: Download build artifacts
        uses: actions/download-artifact@v4
        with:
          path: dist
          pattern: artifacts-*
          merge-multiple: true

      - name: Checksums
        run: |
          ( cd dist && sha256sum * ) > SHA256SUMS
          cat SHA256SUMS

      - name: Attest build provenance
        uses: actions/attest-build-provenance@v2
        with:
          subject-path: 'dist/*'

      - name: Attest SBOM
        uses: actions/attest-sbom@v2
        with:
          subject-path: 'dist/*'
          sbom-path: sbom.spdx.json

      - name: Create draft release
        if: startsWith(github.ref, 'refs/tags/')
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          VERSION="${{ steps.ver.outputs.version }}"
          TAG="${GITHUB_REF_NAME}"
          cat > release-notes.md <<'NOTES'
          ## Verifying this release

          Every artifact carries a keyless build-provenance attestation and an
          SPDX SBOM attestation (Sigstore-backed, no signing key). Verify a
          download before installing:

          ```bash
          # Build provenance (who / what commit / which workflow built it)
          gh attestation verify --repo jordilopezr/LCC <artifact>

          # SBOM (dependency graph that went into the build)
          gh attestation verify --repo jordilopezr/LCC \
            --predicate-type https://spdx.dev/Document/v2.3 <artifact>

          # Offline integrity
          sha256sum -c SHA256SUMS
          ```
          NOTES
          gh release create "$TAG" \
            --draft \
            --title "LCC $VERSION" \
            --notes-file release-notes.md \
            dist/* SHA256SUMS sbom.spdx.json
```

````markdown
# Releasing LCC

LCC releases are built, attested, and published by GitHub Actions
(`.github/workflows/release.yml`) — not on a maintainer's machine. Every
artifact carries a keyless (Sigstore-backed) build-provenance attestation and
an SPDX SBOM attestation. There is no signing key to manage.

## Cutting a release

1. Make sure `main` is at the commit you want to ship.
2. Push a tag named `v<version>`, where `<version>` is the release name used in
   artifact filenames:

   ```bash
   git tag v26H2
   git push origin v26H2
   ```

3. The `Release` workflow runs (tens of minutes: it rebuilds the container
   images and does a full Flutter + Rust build per artifact). It produces:
   - `lightweight-cloud-connector_26H2_amd64.deb`
   - `lightweight-cloud-connector_26H2_x86_64.AppImage`
   - `lightweight-cloud-connector_26H2_amd64.tar.gz`
   - `lightweight-cloud-connector-26H2-1.x86_64.rpm`
   - `SHA256SUMS`
   - `sbom.spdx.json`
4. A **draft** GitHub Release is created with those assets. Review it, then
   publish it manually from the Releases page.

To dry-run the build and attestations without creating a release, use
**Run workflow** (`workflow_dispatch`) and pass a `version` — everything runs
except the release-creation step.

## Verifying a download

Anyone can verify a downloaded artifact against this repository:

```bash
# Build provenance — proves which repo, commit, and workflow built it
gh attestation verify --repo jordilopezr/LCC ./lightweight-cloud-connector_26H2_amd64.deb

# SBOM — the dependency graph that went into the build
gh attestation verify --repo jordilopezr/LCC \
  --predicate-type https://spdx.dev/Document/v2.3 \
  ./lightweight-cloud-connector_26H2_amd64.deb

# Offline integrity — run from the directory holding the downloads + SHA256SUMS
sha256sum -c SHA256SUMS
```

The SBOM is generated by scanning the source tree, so it reflects the real
Rust crate graph (`native/Cargo.lock`) and Dart package set (`pubspec.lock`).
Operating-system libraries bundled by the individual packages are out of scope
for the current SBOM.

## Not covered by CI

- **macOS** builds/notarization (built manually with `scripts/build_macos.sh`;
  real macOS trust needs a paid Apple Developer ID + notarization).
- **Arch** — `packaging/arch/PKGBUILD` remains a source recipe users build.
````

## Manual end-to-end QA (maintainer-run — requires pushing a tag)

The subagents cannot exercise GitHub Actions; the real verification is a live run. After all tasks land, the maintainer runs this once:

1. Push a test tag: `git tag v26H2-rc1 && git push origin v26H2-rc1`.
2. The `Release` workflow completes green (both build legs + the release job).
3. A **draft** release exists holding the four artifacts + `SHA256SUMS` + `sbom.spdx.json`.
4. `gh attestation verify --repo jordilopezr/LCC <each artifact>` passes (provenance).
5. `gh attestation verify --repo jordilopezr/LCC --predicate-type https://spdx.dev/Document/v2.3 <each artifact>` passes (SBOM).
6. `sha256sum -c SHA256SUMS` passes for all four.
7. `sbom.spdx.json` is non-empty and lists recognizable Rust crates and Dart packages.
8. Delete the test tag/draft when satisfied: `git push origin :v26H2-rc1` and discard the draft.
