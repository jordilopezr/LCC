# Diseño: Soporte Multilenguaje (i18n) — 26H2 / SSOT Sprint 17

**Fecha:** 2026-07-16
**Estado:** Aprobado
**Alcance:** Capa Dart/Flutter únicamente. Los errores generados en Rust quedan en inglés (fase posterior).

## Objetivo

Localizar la UI de LCC a inglés (base) y español usando el pipeline estándar de Flutter (`gen-l10n`), con selección de idioma "Sistema + override manual" persistida en settings.

## Decisiones tomadas

| Decisión | Elección |
|---|---|
| Idiomas iniciales | Inglés (base) + Español |
| Errores Rust | Quedan en inglés en esta fase; el mapeo a códigos se pospone |
| Selección de idioma | Sigue al sistema por defecto; override manual en Settings (Sistema / English / Español) |
| Estrategia de migración | Incremental por archivo en rama `feature/i18n`; merge único al final |
| Herramienta | `gen-l10n` oficial: `flutter_localizations` + `intl` + archivos `.arb` |

## 1. Infraestructura

- `pubspec.yaml`: agregar `flutter_localizations` (SDK) e `intl`; activar `generate: true` bajo `flutter:`.
- `l10n.yaml` en la raíz:
  ```yaml
  arb-dir: lib/l10n
  template-arb-file: app_en.arb
  output-class: AppLocalizations
  nullable-getter: false
  ```
- Archivos `lib/l10n/app_en.arb` (plantilla; claves ambiguas llevan `description` en metadatos) y `lib/l10n/app_es.arb`.
- `MaterialApp` en `lib/main.dart`: `localizationsDelegates: AppLocalizations.localizationsDelegates`, `supportedLocales: [Locale('en'), Locale('es')]`, y `locale:` leído del nuevo `LocaleNotifier` (null = seguir al sistema).

## 2. Convención de claves

- camelCase con prefijo de módulo: `settingsTitle`, `sftpUploadFailed`, `doctorCheckDns`.
- Prefijo `common*` para strings repetidos (Cancel, Save, Close, Retry, Error, Copy…): se extraen primero y se reutilizan en toda la app.
- Interpolaciones con placeholders tipados de `.arb` (`"tunnelConnectedTo": "Connected to {instance}"`); plurales con sintaxis ICU cuando aplique.
- **No se traduce:** nombres de producto y tecnologías (LCC, GCP, SSH, SFTP…), comandos de shell, paths, URLs, claves de SharedPreferences, strings de log/debug internos.
- Estimación: ~1,000 literales crudos → ~700–800 claves finales tras deduplicación y exclusiones.

## 3. Selector de idioma

- `LocaleNotifier extends Notifier<Locale?>` en `lib/src/features/settings_provider.dart`, siguiendo el patrón existente de `ThemeModeNotifier`:
  - Estado `null` = idioma del sistema.
  - Persistencia en `SharedPreferences`, clave `app_locale` (valores: ausente/`system`, `en`, `es`).
- UI en `lib/src/features/settings_dialog.dart`: dropdown "Idioma / Language" con opciones Sistema / English / Español.
- El cambio aplica en caliente: `MaterialApp` observa el provider y se reconstruye sin reiniciar la app.

## 4. Strings fuera del árbol de widgets

Regla general: **todo lo que pinta la UI de Flutter se traduce; los mensajes técnicos de backend (Rust y providers profundos) quedan en inglés en esta fase.**

1. **Providers con mensajes de estado/error** (`gcloud_provider.dart`, `sshfs_mount_provider.dart`, etc.): donde sea razonable, el provider expone un dato semántico (enum o código + parámetros) y el widget lo convierte a texto con `AppLocalizations`. Donde el refactor sea caro, el mensaje queda en inglés.
2. **`notification_service.dart`**: recibe textos ya localizados desde el invocador; el servicio no traduce.
3. **SnackBars/diálogos desde callbacks de widgets**: tienen `context`; usan claves normales.

## 5. Orden de migración y verificación

- Rama `feature/i18n`; la app compila y funciona en cada commit.
- **Commit 1:** infraestructura completa + claves `common*` + selector de idioma operativo.
- **Siguientes:** un commit por archivo, de menor a mayor riesgo — diálogos pequeños primero (`account_management_dialog.dart`, `windows_credentials_dialog.dart`, …), `lib/main.dart` (~184 strings) al final.
- Verificación por commit: `flutter analyze` + build. `gen-l10n` falla el build si `app_es.arb` pierde sincronía con la plantilla (red de seguridad).
- Test de widget (smoke): arrancar la app con locale `es` y verificar que el dashboard renderiza.
- QA final: revisión visual manual de overflow/truncado en diálogos en español (textos ~20-30% más largos).

## Fuera de alcance

- Mapeo de errores Rust a códigos + traducción (fase posterior; requiere tocar `native/src/api.rs` y regenerar el bridge).
- Idiomas adicionales más allá de EN/ES.
- Localización de documentación, README o paquetes (.deb/.rpm).

## Riesgos

- **Volumen:** ~700–800 claves; mecánico pero largo. Mitigado por migración por archivo con build verde en cada paso.
- **Strings en providers:** decidir caso a caso enum vs. inglés; el criterio es no emprender refactors profundos en esta fase.
- **Overflow en español:** QA visual al final; los diálogos con layouts justos pueden requerir ajustes menores.
